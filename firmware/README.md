# SENME ESP32 コントローラー

各モードの現行動作・時間配分・操作仕様は[動作仕様書](動作仕様書.md)を参照してください。

MPU6050の揺れでESP-NOWの `START` を送る別ESP32用スケッチは
[sense_sender](sense_sender/README.md) を参照してください。
書き込みは `./firmware/flash.sh --target sense_sender --port <送信側ポート>` で実行できます。

LEDライトとブラシ付きDCモーターを、それぞれNチャネルMOSFETで制御するArduinoスケッチです。
対象は **通常のESP32（ESP32-WROOM搭載DevKit等）／Arduino-ESP32 3.x** です。
使用ボードは [ELEGOO ESP-32 開発ボード USB-C／CP2102・2個セット（B0FT2SJH3H）](https://www.amazon.co.jp/dp/B0FT2SJH3H) です。
商品写真のESP32-WROOM系モジュールとD25・D26・D27・D32・D33の印字を確認し、既存のピン設定で対応しています。
実機確認は未実施です。ESP32-C3、S2、S3などはこのスケッチの対象外です。負荷の型番は未確定のため、電力側は以下の前提・例です。

## 動作

電源投入時は保存値を読み、ESP-NOWの受信待機から開始します。ボタンを短押しして離すたびに、
「シーケンス → 編集1 → 編集2 → ESP-NOW → シーケンス」の順で切り替わります。
シーケンスへ戻る際も①から再開します。シーケンス・ESP-NOWモード中のロータリー操作は無効です。

| 区間 | 時間 | LED | モーターPWM出力率 |
| --- | --- | --- | --- |
| ① | 20秒 | 5秒周期のsin波で0→100→0%。4周期 | 0% |
| ② | 15秒 | 明るさ0%から100%へ直線的にフェードイン | 55%から設定値まで直線的に上昇 |
| ③ | 60秒 | 設定した点灯時間で点滅 | 設定値を維持 |
| ④ | 15秒 | 設定した点灯時間で点滅（補完した仕様） | 設定値から55%まで直線的に下降し、最後に即0% |

合計110秒で①へ戻ります。④の終了でモーター出力を0%・LEDを消灯し、直ちに①の0%から明滅を再開します。追加の消灯待機時間はありません。
①の式は `輝度 = (1 - cos(2π × 経過時間 / 5秒)) / 2` で、位相をずらしたsin波です。

開始時はPWM出力を55%にし、15秒かけて設定最大値へ上げます。設定最大値が55%以下の場合は、その設定値を開始時から維持します（0%設定なら出力しません）。この開始処理はシーケンス・Motor Edit・ESP-NOWに共通です。

### 編集1：LEDの点灯時間

- 周期は55.55ms固定（約18.0018Hz）。厳密な18Hzの周期は約55.5556msですが、指定の55.55msを使用しています。
- 時計回り1クリックで点灯時間を0.5ms増加、反時計回りで0.5ms減少します。
- 範囲は0〜55.55ms。0msは消灯、55.55msは連続点灯、その間は100%の明るさでパルス点灯します。
- 例えば5.0msなら「5.0ms点灯＋50.55ms消灯」です。変えるのは点滅の周期ではなく、周期内の点灯時間です。
- 初期値は5.0ms。モーター出力は0%です。

点灯時間は0.5ms刻みで55.5msまで調整でき、その次が連続点灯の55.55msです。旧設定の56ms連続点灯は読み込み時に55.55msへ移行します。

### 編集2：モーター最大出力

- 時計回り1クリックで1%増加、反時計回りで1%減少します（刻み幅の補完仕様）。範囲は0〜100%、初期値は55%です。
- 入ってから15秒で55%から設定値へ加速します。ロータリー操作は設定値へ反映し、加速中は経過時間に応じた割合を出力します。
- 終了時は現在の出力から15秒かけて55%まで下げ、その後すぐ0%にします。停止完了までSTART受信・モード切替は無効です。
- LEDは加速中の15秒間は明るさ0%から100%へ直線的にフェードインし、加速完了後に編集1の設定で点滅します。
- 出力率は回転数ではありません。低出力で始動しない場合や、負荷によって回転数が変わる場合があります。

### ESP-NOW：実行メッセージで60秒動作

編集2からボタンを短押しすると、LEDを点滅させたまま15秒かけてモーターを減速してからOFFにします。停止完了後にSTART受付を開始し、LEDはシーケンス①と同じ5秒周期のフェードイン・フェードアウトを繰り返して待機します。
フェードは明るさ0%から開始し、30秒を超えてもSTARTを受信するまで継続します。
起動時もESP-NOW待機に入り、STARTを受信するまでモーターは停止したままです。ESP-NOW以外のモードでは実行メッセージを破棄します。

| 受信後の区間 | モーターPWM出力率 | LED | 実行メッセージ |
| --- | --- | --- | --- |
| 0〜15秒 | 55%から編集2の設定値まで直線的に上昇 | 明るさ0%から100%へ直線的にフェードイン | 破棄 |
| 15〜45秒 | 設定値を維持 | 編集1の設定で点滅開始 | 破棄 |
| 45〜60秒 | 設定値から55%まで直線的に下降し、最後に即0% | 同上 | 破棄 |
| 停止後0〜3秒未満 | 0%で待機 | 明るさ0%から5秒周期のフェードを再開 | 破棄 |
| 停止後3秒以降 | 0%で待機 | フェードを継続 | 次の実行を受付 |

加減速を含めて合計60秒です。START受信後はシーケンス①の20秒間の明滅を挟まず、直ちに加速へ移ります。
待機中の有効なメッセージ1件だけを処理し、動作中のメッセージを
後から実行するために蓄積しません。受信コールバックでは待機状態を確認してから本文を調べ、
動作中は本文の解析も行いません。無線自体は有効なままで、アプリケーション側で破棄します。

メイン処理がモーターPWMを0%にし、LEDをフェードへ切り替えた時点から3秒間はSTARTを破棄し、その後に受付を再開します。この間のSTARTは予約しません。起動時とMotor Editからの移行時には、この3秒待機を設けません。停止後の3秒間も短押しでシーケンスへ移れます。
実際の軸の停止を検知しているわけではなく、惰性で回る可能性があります。
動作中のボタン短押しは無効です。待機に戻ったら短押しでシーケンスへ移れます。
ESP-NOWモードではロータリー操作・長押し保存は無効で、編集1・2の設定を使用します。

#### 送信側の設定

- Wi-Fiチャンネル：**1**（スケッチの `ESPNOW_CHANNEL` で変更可能）。送受信側を同じチャンネルにします。
- 宛先：起動ログの `ESP-NOW: MAC=...` に表示される受信側STA MACアドレス。
- メッセージ：ASCIIの **`START`**、5バイト。終端NULを含む6バイトも許可します。
  改行付き、JSON、小文字の `start`、その他のデータは実行しません。
- 暗号化なし。送信側では宛先をESP-NOW peerに登録して送ります。ブロードキャストも受け付けます。
  送信元MACの制限やアプリケーションの実行受付ACKはありません。
- ルーターへの接続は不要です。USBモニターは引き続き `dtr=off,rts=off` を使用します。

送信側でWi-Fi／ESP-NOWの初期化・同一チャンネル設定・宛先peer登録が済んでいる場合の送信例：

```cpp
const uint8_t command[] = {'S', 'T', 'A', 'R', 'T'};
esp_now_send(receiverMac, command, sizeof(command));
```

送信成功の通知だけでは、受信側が動作を開始したとは判断できません。
受信側が動作中なら破棄されます。また、待機に戻った後に届く再送は新しい実行要求になります。

シリアルログは `READY` → `RUNNING (60 seconds)` →
`STOPPED; COOLDOWN (3 seconds; START ignored)` → 3秒後に `READY (waiting for START)` の順で表示されます。

参考：[Espressif ESP-NOW API](https://docs.espressif.com/projects/esp-idf/en/v5.5/esp32/api-reference/network/esp_now.html)。

### 3秒長押しで保存

編集モードで3秒押し続けると、そのモードの設定だけを内蔵フラッシュへ1回保存します。
離してもモードは切り替わりません。シーケンス・ESP-NOWモード中の長押しは無効です。
保存せずに変更した値も、電源が入っている間はモードをまたいで使用します。
再起動すると最後に保存した値へ戻ります。

ESP32向けの `Preferences`（NVS）をEEPROMの代わりに使います。追加のEEPROM部品は不要です。
保存成功時はシリアルモニターに `SAVED`、失敗時は `SAVE FAILED` を表示します。
保存成功時はLEDを明るさ100%で約3Hz、1秒間に3回点滅させます（約167ms点灯／約167ms消灯）。終了後は現在のモードのLED表示へ戻ります。保存失敗時は確認点滅を行いません。確認点滅中もモーター制御は継続します。

## 配線例

スケッチ先頭の定数でピン番号を変更できます。各GPIOは3.3V信号です。

| ESP32端子 | ELEGOO基板の印字 | 接続先 |
| --- | --- | --- |
| GPIO25 | D25 | LED用MOSFETのゲートへ100〜330Ωの直列抵抗を介して接続 |
| GPIO26 | D26 | モーター用MOSFETのゲートへ100〜330Ωの直列抵抗を介して接続 |
| GPIO32 | D32 | エンコーダーA / CLK |
| GPIO33 | D33 | エンコーダーB / DT |
| GPIO27 | D27 | エンコーダーボタン / SW |
| GND | GND | 各MOSFETソース、負荷電源マイナス、エンコーダーCOM、ボタンの反対端 |
| 3.3V | 3V3 | 電源端子のあるエンコーダーモジュールのVCC（3.3V対応品） |

番号は基板の端から数えた位置ではなくGPIO番号です。例えばコードの `25` は基板の `D25` に対応します。
モード切替にはエンコーダーに付属するボタンを使います。基板上の `BOOT`・`EN` ボタンとは別です。

LEDとモーターの各負荷について、`負荷電源＋ → 負荷＋ → 負荷− → MOSFETドレイン` と接続します。
MOSFETソースはGNDへ、ゲート–ソース間には10kΩ程度のプルダウン抵抗を入れ、起動中もOFFに保ちます。
MOSFETは **ゲート電圧2.5〜3.3Vでのオン抵抗が仕様に明記されたもの** を、負荷電流・電圧・発熱に合わせて選定してください。
しきい値電圧だけでは選定できません。PWM対応MOSFETモジュールを使う場合も、3.3V入力・HIGHでONの仕様を確認します。

モーター両端には逆起電力を逃がすフライバックダイオードを並列接続します。
**カソード（帯側）はモーター＋、アノードはモーター−（ドレイン側）** です。
モーターの始動・拘束電流に対応する電源、MOSFET、ダイオードが必要です。
モーターの電力配線はESP32基板を経由させず、電源付近でGNDを共通化します。
電源付近のバルクコンデンサとモーター端子間のノイズ対策コンデンサも、使用モーターに合わせて設けてください。

LEDは電流制限付きのDCライト／LEDストリップを想定しています。裸のLEDやパワーLEDには適切な電流制限回路が別途必要です。
LED・モーターの負荷電力はESP32のGPIOや3.3V端子から供給しません。
この配線はブラシ付きDCモーター用です。サーボ・ステッピング・ブラシレスモーターには別の駆動回路が必要です。

エンコーダー入力は内部プルアップを使用し、接点がGNDへ落ちる方式です。5Vにプルアップされた信号を直接接続しないでください。
時計回りで値が減る場合は `ENCODER_DIRECTION = -1` に変更します。
2クリックで1回しか変わらない機種では `ENCODER_EDGES_PER_CLICK` を4から2へ変更します。

## Arduino CLIでの書き込み（macOS）

対象は `ESP32 Dev Module`、FQBNは `esp32:esp32:esp32` です。
Arduino-ESP32はコンパイル確認済みの **3.3.8** を使用します。
追加ライブラリは不要です。Preferences、LEDC、RMT、Wi-Fi、ESP-NOWはESP32コアに含まれます。

### 自動実行スクリプト

リポジトリのルート（`senme`）から実行します。
先にLED・モーターの負荷電源を切り、ESP32をUSB接続してください。
開いているシリアルモニターは `Ctrl+C` で終了します。

```sh
./firmware/flash.sh --port /dev/cu.usbserial-0001
```

スクリプトはArduino CLIの準備 → ESP32コア3.3.8の準備 → コンパイル → 書き込み →
シリアルモニター起動を順に実行します。CLIがない場合は、インストール済みのHomebrewを使用します。
コアが既に3.3.8なら再インストールしません。ポートは実機に合わせて指定してください。
別の作業ディレクトリから実行しても動作します。

```sh
# ポート一覧の確認
arduino-cli board list

# 書き込みまで実行し、モニターを開かない
./firmware/flash.sh --port /dev/cu.usbserial-0001 --no-monitor

# 実機に書き込まず、環境準備とコンパイルだけ実行
./firmware/flash.sh --build-only

# 環境変数でポートを指定することも可能
export ESP32_PORT=/dev/cu.usbserial-0001
./firmware/flash.sh
```

### 手動で実行する場合

1. 初回のみCLIとボード定義を準備します。CLIが導入済みなら `brew install` は不要です。

```sh
brew install arduino-cli
arduino-cli config add board_manager.additional_urls \
  https://espressif.github.io/arduino-esp32/package_esp32_index.json
arduino-cli core update-index
arduino-cli core install esp32:esp32@3.3.8
```

2. USB接続したボードのポートを確認します。ボード名がUnknownでも、ポートとFQBNを指定できます。

```sh
arduino-cli board list
export ESP32_PORT=/dev/cu.usbserial-0001
```

3. `senme` ディレクトリからコンパイル・書き込みします。
   `senme_controller.ino` と `Control.h` は同じフォルダに置きます。

```sh
arduino-cli compile \
  --fqbn esp32:esp32:esp32 \
  --output-dir /tmp/senme-build \
  firmware/senme_controller

arduino-cli upload \
  --port "$ESP32_PORT" \
  --fqbn esp32:esp32:esp32 \
  --input-dir /tmp/senme-build \
  firmware/senme_controller
```

4. **115200 bps・DTR OFF・RTS OFF** でログを開きます。

```sh
arduino-cli monitor \
  --port "$ESP32_PORT" \
  --config baudrate=115200,dtr=off,rts=off
```

接続後に基板の **EN（RESET）を一度押して離す**と、起動ログを確認できます。
BOOTは押しません。初期設定では次の表示が出ます（保存済みの設定があれば数値は変わります）。

```text
Mode: ESP-NOW; click: next mode; hold 3 seconds in edit mode: save
LED: 5.00 ms ON / 55.55 ms period; motor maximum: 55%
ESP-NOW: READY (waiting for START)
```

モニター終了は `Ctrl+C` です。起動後はSTART受信でモーターの加速が始まるため、
配線を確認してから負荷電源を入れてください。

### 文字化け・接続失敗時

- 実機では `baudrate=115200` だけの指定で文字化けし、
  `baudrate=115200,dtr=off,rts=off` の指定とリセットでログ表示を確認できました。
  スケッチ側も `Serial.begin(115200)` です。文字化け時は上記設定で開き直し、ENを押してください。
- 書き込みが `Connecting...` で止まる場合は、BOOTを押したまま書き込みを開始し、転送開始後に離してください。
- ポートがない場合はUSBデータ通信対応ケーブルと接続を確認し、`arduino-cli board list` で再確認してください。
- ポート使用中のエラーが出る場合は、別のターミナルやArduino IDEのシリアルモニターを終了してください。

参考：[Espressifのボード定義の導入手順](https://docs.espressif.com/projects/arduino-esp32/en/latest/installing.html)、
[DTR／RTSと起動・リセットの関係](https://docs.espressif.com/projects/esptool/en/latest/esp32/advanced-topics/boot-mode-selection.html)。

## 時間精度と実機確認

LED点滅はRMTの1MHzタイマーで周期55,550tick、点灯時間500tick刻み（最大55,550tick）として生成します。点灯区間は100%出力とし、キャリアPWMは無効にしています。
設定保存やシリアル表示中もハードウェアが波形を出し続けます。①の調光は1kHzのPWMを使います。
調光と点滅の切替時には、周期・比較値の反映待ちで約55.55ms消灯します。周期自体の精度はボードのクロック精度に依存します。
設定・明るさの更新時は波形を一度停止して新しい周期を開始します。切替時のパルスは短くなる場合があります。一定設定ではハードウェアが自動反復し、保存や通信によるタイミングの揺れを避けます。
モーターは20kHz・10bit PWMです。モード切替と加減速の更新はメインループで行うため、OSのスケジューリング等による遅延があります。

MOSFET1個による制御では出力を0%にしてもモーターは惰性で回転することがあります。
「減速終了後に実際の回転停止を確認してLEDを消す」ことまで必要な場合は、回転検出とブレーキ可能なドライバーを追加してください。
この実装では15秒の減速終了時のPWM出力0%を停止指令と扱っています。
すべての通常停止（シーケンス・ESP-NOW・編集2終了・シーケンスから編集1への切替）は、現在の出力から15秒でPWM出力率55%へ下げ、最後に即0%とします。
開始時の出力が55%以下なら出力を上げずに15秒維持してから0%にします。既に0%ならそのまま停止します。
LED・モーター制御APIなどでエラーが発生した場合も、最後に正常適用した出力から15秒かけて55%へ減速し、その後0%を指令します。55%以下は15秒維持し、既に0%またはモーター未初期化なら直ちにOFFを指令します。異常時はSTART受付を無効化し、停止処理後も自動復帰せずリセット待ちになります。モーターAPI自体の失敗時は減速を保証できず、その旨をログに表示します。最後の0%指令に失敗した場合は、1秒ごとに0%を再試行します。電源断・CPU停止はこの減速処理の対象外です。

- 起動直後はESP-NOW待機となり、モーター出力0%、LEDが5秒周期で明滅し、START未受信なら20秒を超えても停止を維持すること。
- 待機中の短押しでシーケンス①に入り、LEDが5秒周期で4回明滅すること。
- シーケンスへ切り替えてから20秒で加速開始（LEDは15秒で0%から100%へフェードイン）、35秒で設定出力に達して点滅開始、95秒で減速開始、110秒で出力0%になり①へ戻ること。
- シーケンスから編集1へ切り替えると15秒で55%まで減速後、即0%になること。減速中の再切替は無効になること。
- オシロスコープ等で55.55ms周期と0.5ms刻みの点灯時間を確認すること。0msと55.55msの端点も確認すること。
- 編集2の開始時は15秒で加速し、終了時は15秒で55%まで減速して即0%になること。減速中のSTARTは破棄されること。
- 編集2で出力が1%刻みで変わり、0〜100%に収まること。低出力時の始動・発熱も確認すること。
- 長押しで `SAVED` が1回出て、LEDが100%で1秒間に3回点滅して元の表示へ戻ること。離してもモードが変わらず、点滅中もモーター制御が続くこと。保存失敗時は確認点滅しないこと。
- 各設定を保存して電源を入れ直すと復元されること。未保存変更は復元されないこと。
- モーター駆動中にエンコーダーの誤カウントやESP32の再起動が起きないこと。
- ESP-NOW待機中はLEDだけが5秒周期でフェードし、30秒を超えてもモーターが動かないこと。停止直後にフェードを再開し、STARTは3秒間破棄した後に受付を再開すること。
- ESP-NOWモードで `START` を送り、15秒加速・30秒維持・15秒減速（55%到達後、即0%）して停止すること。
- 動作中に繰り返し送信しても、延長・再実行されないこと。送信をやめて待機へ戻っても勝手に再開しないこと。
- 待機に戻ってから新しい `START` を送ると再び実行すること。他モードや不正なメッセージでは開始しないこと。
- ESP-NOW動作中の短押しでモードが変わらず、待機中なら切り替えられること。
- 無線通信中もLEDの周期、モーターの加減速、電源の安定性に問題がないこと。

ホスト側のロジックテストは、`firmware` フォルダで次のように実行できます。

```sh
c++ -std=c++17 -Wall -Wextra -Werror tests/control_test.cpp -o /tmp/senme-control-test
/tmp/senme-control-test
```

## ボタン誤判定の調査・修正（2026-10-03）

ボタンの読み取りが途切れた間に離された短押しを、経過時間だけで長押し保存に分類する経路を再現し、修正しました。100 msを超えるサンプリング中断が操作中にあった場合、その操作を破棄し、25 ms以上の安定したリリース後に次の押下を受け付けます。中断中の押下時間は確認できないため、保存や遅延したモード切替を実行しません。

シリアルには `BUTTON: CLICK (… ms)`、`BUTTON: LONG PRESS (… ms)`、読み取り中断時には `BUTTON: sampling gap >100ms…` が出ます。短押しのつもりで `LONG PRESS (3000 ms)` が出る場合は、実際の接点・GPIOの状態も確認が必要です。この修正で実機症状の原因が確定したわけではありません。

モード切替に伴う15秒のモーター停止中、ESP-NOWの受付後〜運転終了までの短押し無効は従来仕様です。無効な操作は予約されません。`Mode change ignored…` のログでボタン判定自体の失敗と区別できます。

## モード切替のLED通知（2026-10-03）

短押しによるモード切替が成立すると、LEDが短く2回点滅します。消灯100 ms → 点灯80 ms → 消灯100 ms → 点灯80 ms → 消灯140 ms、合計0.5秒で通常の表示に戻ります。Save成功時の「約1秒で3回点滅」と区別できます。

停止中・ESP-NOW運転中などで短押しを無視した場合は、切替通知を出しません。通知はLEDだけを一時的に上書きし、モーター制御・ボタン読取り・ESP-NOW処理は継続します。通知の間もシーケンスの時間は進みます。連続して切り替えた場合は最新の通知を最初から表示し、Save通知中に切り替えた場合も切替通知へ置き換えます。

## ボタン入力の極性（2026-10-04）

実機で短押しだけを行った際、旧判定（LOWで押下）では2.4〜2.8秒のCLICKや3秒のLONG PRESS、意図しないSaveが記録されました。押していない時間を押下時間として数えている可能性が高いため、このController用の `BUTTON_PRESSED_LEVEL` を `HIGH` に変更しています。実機で短押し時間と無操作時のログを確認してください。起動ログにはGPIO27のレベルと設定した押下レベルを表示します。

GPIO27の `INPUT_PULLUP` は継続しています。通常の「押すとGNDにつながる」常開スイッチを使う場合は `BUTTON_PRESSED_LEVEL = LOW` にしてください。今回の変更は自動極性判定ではありません。

修正版をControllerへ書き込み、起動時GPIO27=LOWを確認しました。実機の短押し3回は145 ms・174 ms・197 msのCLICKとして認識され、ESP-NOW→SEQUENCE→EDIT 1→EDIT 2へ切り替わりました。この確認中にLONG PRESSやSaveの誤検出はありません。保存設定（LED 1.50 ms、モーター最大93%）は保持しています。

## 点滅時の明るさ（2026-10-04）

点滅時の明るさを100%へ戻しました。RMTのキャリアPWMは無効にし、点灯区間は連続HIGH、消灯区間はLOWです。周期55.55 msと設定点灯時間は維持します。点灯時間1.50 msでは周期全体の平均出力は約2.7%です。
開始フェードは15秒で0%→100%、モーター開始・停止は55%です。
