# Zoetlamp「千目灯籠」を作った話

鈴を鳴らすと、大きな球体に並んだ目玉が動き始める。

2026年のBurning Japanに持っていったのは、そんな作品だった。名前は「千目灯籠」。直径は60cm、球体だけで約7kg。もともとは直径18cmくらいのランプを作っていたのだけれど、安易な考えだけどとりあえずでかいものを作ってみた。

目玉の動きを考え、球体を印刷し、つなぎ合わせて、回す仕組みを作る。最後にはお札で結界まで張ることになった。そのあたりを、順番に書いてみようと思う。

## 回して、光らせると、模様が動く

この1年ほど、「zoetlamp」という作品を作り続けている。ゾートロープ（zoetrope）とランプ（lamp）を合わせて、zoetlamp。

仕組みは、ランプシェードを回しながら光を点滅させるというもの。すると、表面に並んだ模様が動いて見える。

![zoetlampの動作の様子。](images/zoetlamp.gif)

これまでは、抽象的な模様が動くランプシェードを作ってきたけど,今回はそこに、千鬼夜行というテーマからもう少し具体的なモチーフを入れることにした。

## 大きさを決めたのは、部屋のドア

2026年のBurning Japanのテーマは「千鬼夜行 || Senki Yagyo」。実は僕もこのテーマに投票していたので、決まったときから、何か妖怪っぽいものを作りたいと思っていた。

せっかく会場へ持っていくなら、いつもより大きくしたい。それまで直径18cmくらいだったものを、今回は一気に60cmにすることにした。

では、なぜ60cmなのか。

部屋のドアから出せる大きさが、そのくらいだったから。ぎりぎり通せそうなのが50〜65cmくらい。大きなものは作りたいけれど、完成しても部屋から出せないのでは困るので。作品のサイズは、ドアのサイズの事情で決まった。

## 気持ち悪いけど、楽しそう

モチーフに選んだのは、妖怪の「百目」。

ランプシェードいっぱいに目玉があって、それがうごめき始める。気持ち悪い。けど、きっと楽しい。目玉ならアニメーションもシンプルに作れそうで、初めて大きなものに挑戦するにはよさそうだった。

名前はテーマの「千鬼夜行」に合わせて、「百目」から「千目」へ。和風に寄せるため「ランプ」を「灯籠」に変えて、「千目灯籠」と名付けた。

## 球体を作る前に、まずは平面で考える

いきなり球体の上で動きを考えるのは難しいので、まずは平面から始める。これは、これまでのzoetlampでも同じ。平面なら、p5.jsやWebGLで動きを試しやすい。(最初から3次元で考えられたら、また違うものが作れるのかもしれない)

目玉を渦巻き状に並べて、外側に向かって一定の速さで動かす。ただ、それだけだと目玉の間に余白が多い。そこで螺旋を二重にして、間にも目玉を並べられるようにした。

| 赤い点で示した配置 | 赤と青の点を重ねた配置 |
| --- | --- |
| ![赤い点が渦巻き状に並ぶ平面上の配置図。](images/reddots.png) | ![赤と青の点を組み合わせた二重の螺旋の配置図。](<images/blue and red.png>) |

左がもとの配置で、右が二重にしたもの。こうして、最終的には482個の目玉が並ぶことになった。

## 目玉にも、パラパラ漫画を用意する

ちょうどWGSLの勉強も兼ねて、「shaderbook」というWebアプリを作っていた。そこにパラパラ漫画モードを追加して、目玉のアニメーションを作った。

![shaderbookのパラパラ漫画モード。目玉のアニメーションをコマごとに一覧表示している。](images/flipbook.png)

目の向きが変わったり、まばたきしたり。その変化をコマごとに並べて確認できる。球体に載せる前に、まずはここで目玉を動かしてみる。

## 絵を印刷するかわりに、厚みで描く

目玉の絵ができたら、次は球体に載せていく。

ただ、zoetlampでは、模様を3Dモデリングしたり表面に画像を印刷するわけではない。「リソファン」という技法で、画像の濃淡をプラスチックの厚みに置き換えている。

明るく見せたいところは薄く、暗く見せたいところは厚くする。そこへ裏から光を当てると、薄い部分は光をよく通し、厚い部分は通しにくい。その差で、透かし絵のように絵が浮かび上がる。

![リソファンの様子。](images/rith.gif)

こんな感じ。こちらのモデルは、茶臼山動物園のレッサーパンダ、ミロ君。

目玉も同じように、絵の濃淡を厚みに変えて3Dプリントしていく。

## 大きくすると、一度では印刷できない

これまでのサイズなら、ランプシェードは丸ごと一度で印刷できた。(20時間ぐらいかかるけど。。)でも、直径60cmとなると、いくつかに分けないと出力できない。

ここで気になったのが、目玉の途中に継ぎ目が入ってしまうこと。つないだところで絵がずれたら、せっかくの動きも崩れるかもしれない。

そこで、目玉の周りに四角い枠を付けることにした。目玉そのものを切り分けず、枠のところで分けられるようにする。

![赤と青の配置点の周りに四角い領域の境界線を引いた平面図。](images/withlines.png)

点だけだった配置に枠を付けると、こんな形になる。

これを球体にして、厚みを付けて、印刷データにする。その一連の作業ができるアプリも作った。処理の流れは次のとおり。

1. 球面を、渦巻きに沿って並ぶ四角い領域に分ける。
2. それぞれに目玉のテクスチャを貼り付ける。
3. 絵の濃淡を厚みに変えて、リソファンにする。
4. 3Dプリント用のSTLファイルとして出力する。

![球体シミュレータの画面。目玉のテクスチャを貼った球体と、形状や表示を調整する操作パネル。](images/sim.png)

画面上で形を確認しながら調整して、そのまま印刷データを出せる。ここまで来て、ようやく実物を作る準備が整った。

## 86ピースをつないだら、1か月たっていた

フィラメントはPETGにした。PLAに比べてしなりがあることが、選んだ理由。

球体は86ピースに分けて印刷した。もちろん、印刷しただけでは球体にならない。ここから、ひとつずつつないでいく。

基本は摩擦溶接。隙間を埋めたいところや、もう少し補強したいところには、はんだごてによる溶接も使った。この合わせ技で、少しずつ球体にしていった。

印刷から溶接まで、合わせておよそ1か月。完成した球体は約7kgになった。

画面の中では簡単に回せた球体も、実物になると結構な重さがある。次は、これを支えて回す仕組みが必要になる。

## 7kgの球体を、どう支えて回すか

全体の構造は、下の図のようになっている。

![千目灯籠の構造断面図。球体の下部を台座と固定板で挟んで固定し、台座の下にギアとターンテーブルベアリングを配置する。中央にライト、右側にモーター、机の下段にESP32を置く。](images/senme-cross-section.png)

球体は、下から支える台座と、内側に置いた固定板で挟んで固定する。その下にギアとターンテーブルベアリングがあって、横のモーターから力を伝えて回す。ライトは球体の中央、制御用のESP32は机の下段に置いた。

図は手描きの断面図を清書したもので、寸法や部品の形は簡略化している。

回す仕組みは、球体を作るのと並行して考えていた。ベアリングは直径21cmくらいのものを使い、中央には照明の光を通す穴を空けておく。

悩んだのは、モーターの力をどう伝えるかだった。以前プーリーベルトを使ったときは、モーターの位置を少し変えるだけでベルトが外れやすくなるなど、調整がシビアだった。その経験もあって、今回はギアを使う方向で考えた。

大きい方のギアは直径22cmくらいを想定して、モーターの回転数から歯数やギア比を考えていった。シミュレーションでは、リフレッシュレートを17Hzにすると43rpmになる。これはあくまでシミュレーション上の条件で、実機の測定値ではない。

## 回すことだけ考えていたら、止まるときが気になった

完成が近づいた頃、モーターの特性で気になることが出てきた。

選んだのは高トルクのモーター。力はあるけれど、外から回そうとしても簡単には回らない。逆駆動がしにくいタイプだった。

もし電源が突然落ちたら、モーターは急に止まる。でも、球体の方はそのまま回り続けようとする。その力が固定部にかかったらどうなるだろう。最悪、つなぎ合わせた目玉のパーツがばらばらになるかもしれない。

1か月かけてつないだ球体なので、それは避けたい。

そこで、ワンウェイクラッチを自作した。モーターで回すときは力を伝えて、球体が惰性で回るときは空転できるようにする仕組みだ。

![ワンウェイクラッチの内部構造を示すCAD画像。外周のギアの内側に、中央のハブから伸びる3本の爪が配置されている。](../motor_gear_38_oneway_open.png)

こちらが内部の構造。回すためのギアに、止まるときのための仕組みも加わった。

## 光と回転は、現地で合わせられるように

台座には40×60cmくらいの木の板とVP20の塩ビパイプを使う構造を考えた。内側にはモーターや電子回路を置く棚も作り、パイプを固定する部品などはOpenSCADで設計して3Dプリントした。

照明は24VのCOBタイプのLEDテープ。MOSFETで点滅や明るさを制御し、全体の制御にはESP32を使うことにした。

ゾートロープは、回る速さと光が点滅するタイミングで見え方が変わる。そこで、調整用のロータリーエンコーダーを付けて、回転速度と点滅周期を現地で調整できるようにした。

## スイッチを入れるより、鈴で起こしたい

作品を動かすきっかけも、途中で何度か変わった。

最初に考えたのは、神社の鈴緒を引くような仕組み。ただ、嬬恋の風など、現地の環境に合わせてセンサーを調整するのが難しく、この方法はあきらめた。

最終的には、テーブルに黒い八角形の箱を置く形に落ち着いた。その箱を振って鈴を鳴らすと、作品が動き始める。

鈴を鳴らすと、千目灯籠が「目覚める」。起動する操作も、作品の雰囲気に合わせたかった。

## 作品の次は、屋根をどうするか

Burning Japanは屋外なので、作品ができても、それだけでは展示できない。雨や風をどうするかも考えないといけない。

大きな傘のようなもの、透明なドーム、PVCパイプで組むティピー型やAフレーム型のシェルター。いろいろ考えたけれど、建造物まで作る時間はなかった。

そこで、手持ちのLOGOSのツールームテントを使うことにした。インナーテントを外して奥に作品を置き、手前にゴザを敷く。作品を置く場所と、座って眺める場所を、ひとつのテントに収めることにした。

## 最後は、お札で結界を張る

雨風とは別に、もうひとつ気になっていたことがある。本体を触られてしまうことだ。

今回の作品は、球体の表面の模様が大事になる。汚れてしまうと、アニメーションの見え方が崩れるかもしれない。できれば、少し離れて見てほしい。

そして、メイカー系のイベントと違って、ここは酔っ払いも多い。

ということで、余ったフィラメントでお札を作って、結界を張ることにした。妖怪の作品なので雰囲気にも合うし、近づきすぎずに見てもらうための境界にもなる。結界には、わりと現実的な役目もある。

## 少し奥まったところで、見つけてもらいたい

僕はBurning Manで、Deep Playaに置かれたアートを探して歩くのが好きだ。街の中心から離れて歩いていると、「こんなところに、こんなものが？」という出会いがある。あの感じが楽しかった。

それに、今回は技術的にも暗い場所がよかった。周囲が明るいと、光の点滅で作るアニメーションが見えにくくなってしまう。

そんな理由から、フリーキャンプエリアの奥の方に置くことになった。

## 5日間、回しきった

10月7日に会場へ向かい、翌8日に設置を終えた。

![テント内で点灯する千目灯籠。周囲にはお札を吊るし、手前には起動用の黒い八角形の箱と観覧用のゴザを配置している。](images/img.jpg)

奥に千目灯籠、周囲にお札、手前に鈴を鳴らすための箱。座って見るためのゴザも敷いて、こういう展示になった。

細かいトラブル(配線が回転に引っかかり断線するとか。。)はあったけれど、夜だけとはいえ、5日間回しきれた。

## 感想

企画から展示まで約3か月。この1年zoetlampでつかんだ勘所も大きいけれど、AIによる実装とテストのループが高速で回せたのがでかい。シミュレータやSTL化のコードは99％読んでいないし、1行も書いていない。配置のアルゴリズムや方針は細かく話し合い、実装とテストはAIに任せた。1年前ならシミュレータ作るので精いっぱいだったと思う。この半年の変化は本当に恐ろしい。

「もっと目立つ場所なら、たくさん見てもらえるのに」とも言われた。そういう声をもらえた時点で大成功だし、たくさん見られたから成功というわけでもないだろうと思う。

一番勉強になったのは、クジラの中で遊んでいた子供達に遠くで光ってるあれは見たか？と聞くと「見た見た、気持ち悪かった！ 夢に出そう！」。遠くで何か光っているのが気になって、見に行ったそうだ。その好奇心とフットワークの軽さは、やっぱり見習いたい。

## Appendix：技術スタック

今回使ったシミュレータやデータ作成用のツールは、すべて自作したもの。CADデータも、OpenSCADでコードを書いて形を作るか、自作ツールからエクスポートして用意した。作品だけでなく、それを作るための道具も作りながら進めた。自作と言っても、99％はCodexとClaudeが作ったんだけどね。残り1％には、まだ人間が介在する余地がある！

### 構成ポンチ絵

![千目灯籠の構成ポンチ絵。MPU6050とESP32で揺れを検知し、ESP-NOWで受信側ESP32へ開始指令を送る。MOSFETを介してLEDとDCモーターを制御し、ギアで球体シェードを回転させる。](images/senme-system-overview.png)

黒い八角形の箱を振ると、MPU6050で検知した揺れをきっかけに送信側ESP32が`START`を送る。受信側ESP32はESP-NOWモードで待機しているときに指令を受け付け、照明とモーターを動かす。ロータリーエンコーダーはモード切替と設定に使う。

部品のつながりを説明するための図なので、外観・配線・寸法は簡略化している。内蔵imagegenで生成し、[生成プロンプト](images/senme-system-overview.prompt.txt)も保存している。

### シミュレータとCADデータ

| 対象 | 技術・形式 | 何に使うか |
| --- | --- | --- |
| 自作の球体シミュレータ | TypeScript、Three.js、Vite、HTML/CSS | 球体リソファンの3Dプレビュー、形状調整、STL出力。ブラウザ上で動くWebアプリ |
| シミュレータの開発環境 | Node.js 22.12以上、npm | 開発サーバー、ビルド、テスト。依存関係は[package.json](../simulator/package.json)に記録 |
| 機構部品のCAD | OpenSCAD、BOSL2 | ギア、支持部品、固定具、配線ボックス、八角形の筐体をコードで設計 |
| 設計・造形データ | SCAD、STL、SVG | SCADは寸法を変更できる設計ソース、STLは3Dプリント用のメッシュ、SVGはお札などの2D図形 |
| ギアの動作確認 | OpenSCADのアニメーション | 歯数比から回転角を計算して、かみ合いの様子を表示 |
| 球体の造形材料 | PETG | 本記録の球体は86ピースを印刷し、摩擦溶接とはんだごてで接合 |

ここでいう「シミュレータ」は、球体の形を確認して印刷データを作るためのアプリ。ギアのアニメーションも含め、荷重・摩擦・変形を解く物理解析ではない。起動方法は[simulator/README.md](../simulator/README.md)にまとめている。

### 電子パーツと制御

| 部品・技術 | 用途・記録されている仕様 |
| --- | --- |
| ESP32-WROOM系開発ボード | 揺れ検知送信側とLED・モーター制御側に各1台。ファームウェア資料にはELEGOO ESP-32（USB-C／CP2102）の記載あり |
| MPU6050 | 加速度を使った揺れ検知。ESP32とはI2Cで接続 |
| 押しボタン付きロータリーエンコーダー | モード切替、回転速度・光の点滅周期などの調整。型番は未記録 |
| 24V COBタイプのLEDテープ | 球体内部の照明。製作記録には24V・48WのLED回路の記述あり。商品型番は未記録 |
| ブラシ付きDCモーター | ギア機構を通じて球体を回転。商品型番・定格は未記録 |
| NチャネルMOSFET | LEDとモーターをそれぞれ駆動。型番は未記録 |
| 電池・負荷用電源 | 送信機とLED・モーターへの給電。電源の型番・電池容量は未記録 |
| ESP-NOW | ESP32間の開始指令の無線通信。ルーターへの接続は不要 |
| RMT／LEDC | ESP32の周辺機能。RMTでLED波形、LEDCでモーターPWMを生成 |
| Preferences／NVS | 設定値をESP32内蔵フラッシュに保存 |

配線や書き込みの手順は、[コントローラー](../firmware/README.md)と[揺れ検知送信機](../firmware/sense_sender/README.md)の資料にまとめている。ファームウェアの資料ではLEDを汎用的に扱っているけれど、ここでは実際の製作に使った24V COB LEDテープについて書いている。

### 開発言語

| 言語 | 担当 |
| --- | --- |
| TypeScript、HTML/CSS | 球体シミュレータの形状処理・画面 |
| C++ | ESP32のArduinoスケッチと制御ロジックのテスト |
| OpenSCAD言語 | 機構部品のパラメトリック設計 |
| Bash | Arduino CLIによるビルド・書き込みの自動化 |
| WGSL | 初期の目玉表現を検討した別プロジェクト「shaderbook」で使用。本リポジトリの球体シミュレータとは別 |

ESP32の開発にはArduino-ESP32 3.3.8とArduino CLIを使用。シミュレータ側にはNode.jsのテスト、TypeScriptの型チェック、ESLintがあり、ファームウェア側にはPC上で動かすC++のロジックテストがある。
